## Overview

PM Career Ops is a full-stack job application tracker I built to replace the chaotic spreadsheet-and-sticky-note system most job seekers rely on. It treats the job search like a product problem — a pipeline that needs stages, metrics, and the right tooling to run efficiently.

[Live App →](https://pm-career-ops.vercel.app) &nbsp;|&nbsp; [View on GitHub →](https://github.com/VithusanU/pm-career-ops)

## The Problem

The PM job search is high-volume and high-stakes. At any given point you're tracking 30+ applications across different stages, companies, contacts, and follow-up deadlines — while simultaneously prepping for phone screens, practicing case studies, and managing outreach. A spreadsheet works until it doesn't. It stops working fast.

The core issues with spreadsheets:
- No visibility into what stage each application is in at a glance
- No reminder or next-action system — things fall through the cracks
- No way to capture ATS keywords per role to align your resume
- No single place for contact info, recruiter names, and job post links
- No signal on which applications are worth the most energy

## The Solution

A purpose-built application OS. Everything in one place — a visual pipeline by stage, fit scoring, ATS keyword tracking per role, contact management, and a next-action system so nothing slips.

## Key Features

- **AI-Powered Job Import** — Paste any job posting URL and the app auto-extracts company, role, ATS keywords, and description notes. Uses JSON-LD structured data, OpenGraph tags, and a Jina AI headless-browser fallback to bypass bot protection on sites like LinkedIn and Indeed.
- **Application Pipeline** — Track every role across 8 stages: Researching → Applied → Phone Screen → Interview → Final Round → Offer → Rejected / Withdrawn.
- **ATS Keyword Tracker** — Stores the PM-relevant keywords found in each job description so you know exactly what to mirror on your resume and in your answers.
- **Fit Scoring (1–100)** — Score each role by fit to prioritize where to focus your energy and prep time.
- **Next Action System** — Every application holds a next step and a date, so the tracker tells you what needs to happen and when.
- **Contact Tracking** — Recruiter and hiring manager details linked per application.
- **PM Resources Hub** — A curated library of PM interview frameworks, case study prep guides, and the exact job boards where PM hiring managers actually source candidates.

## Tech Stack

- **Frontend:** Next.js 14, TypeScript, Tailwind CSS
- **Backend & Auth:** Supabase (PostgreSQL + Row-Level Security + Google OAuth)
- **AI Integration:** Server-side HTML scraping (JSON-LD, OpenGraph, title fallback) with Jina AI bypass for bot-protected pages
- **Deployment:** Vercel

## Iteration in Practice — The Import Feature

The job import feature is a good case study in how a real product problem compounds once users start using something.

**v1:** Server-side URL fetch → extract company, role, and keywords from page HTML. Worked on most ATS platforms (Greenhouse, Lever, Workday, Ashby).

**The failure signal:** LinkedIn and Indeed — the two sites where most job searches start — returned blocked or empty responses. Users pasting the most common job URLs got no import, no feedback, and no explanation. From a user's perspective the feature just didn't work.

**Diagnosis:** Both platforms actively block server-side requests. This is intentional — bot protection is core to how they operate. A server-side fetch would never reliably work here.

**Iteration 1 — Jina AI fallback:** Routed bot-blocked URLs through Jina AI's headless browser service, which renders the page before returning the content. This recovered the import for many LinkedIn and Indeed URLs. New failure signal: some pages returned Cloudflare challenge pages even through Jina, which the parser was reading as content and extracting garbage (most memorably: "Reviews" as the company name instead of the actual employer).

**Iteration 2 — Bot signal detection + URL slug extraction:** Added detection for Cloudflare/bot-block signals in the returned content. When detected, the system falls back to extracting the company name directly from the URL slug (`ca.indeed.com/cmp/Inbox-Monster` → "Inbox Monster"). Not perfect, but a meaningful improvement — the user gets a partially filled form with the company name rather than a confusing error.

**Iteration 3 — Bookmarklet for client-side extraction:** Built a browser bookmarklet that runs in the user's own browser session (where LinkedIn and Indeed have no reason to block them), extracts the job data from the live DOM, and opens the pipeline page with a pre-filled form. This solved the root problem — the import now works from inside the user's authenticated session, where bot protection doesn't apply.

Each failure revealed something real about the technical constraints of the two biggest job sites on the internet. The bookmarklet wasn't in scope for v1. It became the most reliable import method.

## What I Learned

The ATS keyword extraction reframe was the most useful product insight from the project. It started as a convenience feature — grab the job description keywords automatically. In practice, it became the core job-to-be-done for anyone applying at volume. When you have 40 open applications, the keywords are what you use to quickly align your resume and answers to each role. That realization changed how the feature was prioritized and how prominently it was surfaced in the UI.
